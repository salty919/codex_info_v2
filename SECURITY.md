# Security threat model and acceptance gate

Contract identifier: `SECURITY_CONTRACT_V3_2026-08-21`.

This versioned document defines the finite attack surface that R17 verifies. Any asset, input, trust boundary, or control change requires a new identifier plus G1/G3/G4 reruns. It does not claim that unknown vulnerabilities cannot exist.

## Assets and trust boundaries

- Assets: Codex/ChatGPT account metadata, session history, local usage database, authentication URL, UI integrity, loopback APIの公開スナップショット, Windows監視クライアントの表示整合性, and the user's process privileges.
- Untrusted inputs: Codex app-server JSON-RPC, `thread/list` paths, session JSONL, migration/history files, environment-provided paths, authentication URLs, CLI port values, loopback HTTP requests, Windowsクライアントが読むloopback HTTP応答, X11 properties/events, and all strings rendered in the UI.
- Local same-UID administration of this repository and Codex installation is trusted. World/group-writable executables, paths outside the configured roots, symlinks crossing a root, malformed/oversized data, and another X11 client are not trusted.
- X11 cannot isolate clients on the same display. The application must not treat X11 as a confidentiality boundary; this residual platform limitation must be reported.

## Required controls

1. Resolve both the Codex executable and browser opener executable to absolute regular files before spawning them. Explicit overrides must be absolute and may not be symlinks. A PATH launcher symlink is accepted only after canonicalizing it to its final regular target; the target and every canonical parent are then validated. Reject a relative PATH entry, non-regular/non-executable target, or file/parent writable by group or other. WSL DrvFS is the one explicit compatibility case because it reports synthetic `0777`: accept a component only when `/proc/self/mountinfo` identifies its containing mount as `9p` with `aname=drvfs` and the component owner equals the process UID. This does not make Windows ACLs an application security boundary; the installed Codex binary remains part of the stated same-UID local administration trust assumption. Never invoke a shell; pass each argument directly to `Command`.
2. Parse authentication URLs structurally. Allow only scheme `https`; empty username; no password; host exactly `openai.com`/`chatgpt.com` or a DNS-label-boundary subdomain ending in `.openai.com`/`.chatgpt.com`; and no explicit port or port 443. Path and query are allowed, fragment is rejected. The entire input must be at most 2,048 Unicode scalar values. Pass an allowed URL as one structured process argument; never use suffix substring matching or a shell.
3. Accept `thread/list` rollout files only when their canonical regular-file path remains under the canonical Codex sessions root. Reject symlinks and paths outside that root.
4. Traverse session data without following symlinks. Limit traversal to depth 8, 4,096 regular files, 256 MiB per file, 4 MiB per JSONL line, and 2 GiB total. Exceeding a limit fails closed for that input without crashing the UI or suppressing an independently valid quota snapshot. The 2026-08-15 live regression corpus reached 281 files, 68,031,955 bytes/file, and 254,974,241 bytes total; the revised finite limits retain resource bounds while covering that observed workload with headroom.
5. Limit each JSON-RPC line to 4 MiB bytes, require valid UTF-8, cap JSON nesting depth at 128, reject duplicate keys in every object instead of applying first/last-wins semantics, limit ignored/mismatched messages to 1,024 per request, and limit response wait to 15 seconds. Malformed, oversized, over-depth, duplicated-key, mismatched, stalled, or terminated responses become a concise user-safe error.
6. Reap the app-server child on Stop, channel closure, initialization failure, and every early-return path. Do not leave an orphan process.
7. Normalize every external UI string to one line before storing/rendering: replace C0/C1 controls, CR/LF/tab, U+2028/U+2029, and bidi formatting/isolate controls with an ASCII space, then collapse consecutive spaces. Bound the normalized value by Unicode scalar count: email 254, plan 64, model 128, thread title 512, limit name 96, and status 160. Over-limit email/thread-title/limit-name/status display strings are shortened to the first `limit - 1` Unicode scalar values plus `…`; this is never applied byte-wise. Plan is an exact schema enum and over-limit/schema-external values reject the response. Model values of 129 scalar or more reject the candidate rollout file; accepted complete model values remain internal, while the AccountActivity display label has the stricter 24-scalar rule. Authentication URLs are rejected rather than shortened when over 2,048 scalar values. Validate every numeric field against the partitions in `VERIFICATION_PLAN.md`; reject negative, fractional where an integer is required, non-finite-equivalent, out-of-domain, and overflow values. Never display raw JSON-RPC error objects or secret-bearing payloads.
8. Use parameterized SQLite statements and `Cargo.lock`. Create the application data directory with mode 0700 and database with mode 0600 on Unix; reject configured DB/session/migration roots that are relative, symlinks, non-directories where a directory is required, or escape their canonical configured root. `run.sh` and validation commands use `--locked`.
9. Keep product source free of explicit `unsafe` unless a separately reviewed exception is documented. The crate uses `deny(unsafe_code)` rather than `forbid(unsafe_code)` because generated Slint code contains its own reviewed lint allowance; a source scan separately rejects explicit `unsafe` in `src/`, `build.rs`, and `run.sh`. Do not persist or print credentials, tokens, private keys, or authentication cookies.
10. The REST API always binds the numeric loopback address `127.0.0.1`; public CLI input can change only the port with `--port PORT`. Reject zero, overflow, negative, non-numeric, missing, duplicate, or malformed port values without falling back to a broader address. It permits only `GET /v1/health` and `GET /v1/details`, returns JSON `404` for unknown paths and `405` for non-GET requests to known paths, sets `Cache-Control: no-store`, and emits no CORS policy. HTTP parsing and connection lifecycle are delegated to Axum/Hyper rather than a handwritten parser. The API contains only a validated immutable whitelisted snapshot supplied by the producer; handlers do not directly touch Slint, Codex RPC, SQLite, local files, authentication URLs, email, raw errors, paths, credentials, or tokens. Snapshot publication rejects an incomplete or invalid time/quota/model/history/thread document and retains the prior complete snapshot. Loopback access is a same-host boundary; the documented Windows route is SSH local port forwarding, whose peer authentication and transport encryption remain SSH's responsibility.
11. The Windows monitor uses `http://127.0.0.1:8787/v1/health` only to confirm service readiness and `http://127.0.0.1:8787/v1/details` as its sole runtime-data destination. It does not accept an editable HTTP/LAN/Internet endpoint, authentication header, token, cookie, password, or private key. Setup may accept an SSH user and host/IP or SSH config `Host` alias only as transient memory input and launch Windows `ssh.exe` directly with an argument list; it must not persist the input, SSH command, credentials, keys, or resolved config fields. Its `HttpClient` allows only GET to the two fixed URIs and disables proxy use, redirects, cookies, and automatic decompression. It limits response headers to 8 KiB and `/v1/details` transfer-decoded body bytes to 32 MiB; details also rejects more than 128 periods, 44,640 one-month samples, 256 threads, or 3 models. It requires `application/json`, the complete exact finite v1 schema, every required key, no unknown/case-altered/duplicate key at any object depth, exact numeric domains, and bounded text without control/bidi formatting characters. Transport failures and unsafe responses retain the independently validated last-good details snapshot and display a bounded localized error; response bodies and exception text never reach the UI or logs. The client performs an immediate poll, waits 10 seconds after each completed cycle, has a 1-second request timeout and at most one in-flight cycle, and cancels active polling when the window closes.
12. The Windows update client is a separate trust boundary and has no editable endpoint. It may GET only the public releases for exact repository `salty919/codex_info_v2`, the exact release manifest/installer asset for a validated `windows-vX.Y.Z` tag, and at most three HTTPS redirects restricted to `api.github.com`, that repository's `github.com/.../releases/...` paths, and `release-assets.githubusercontent.com`. Proxy, cookies, automatic decompression, automatic redirects, credentials, and request bodies are disabled. Release-list bytes are limited to 1 MiB, manifest bytes to 16 KiB, and Setup bytes to 256 MiB. Draft/prerelease releases, nonstable versions, unknown/duplicate/missing manifest fields, tag/version/name/URL/size/SHA mismatch, truncated/oversize content, and hash failure are rejected with no installer launch. Startup performs check-and-notify only. Network download and the ordinary interactive Setup launch occur only after the user activates the conditional update action; silent install, unattended apply, and automatic restart are prohibited. Partial files are removed and updater failure never replaces the loopback client's last-good snapshot or backend status.

## Security regression evidence

- Unit tests: Codex/browser executable validation including parent permissions; auth URL exact host/subdomain, lookalike host, userinfo, port, fragment, path/query, and length cases; configured root and rollout containment/symlink rejection; traversal/line/file limits; RPC mismatch/oversize/timeout; child cleanup; database/directory modes; Unicode scalar shortening; URL length rejection; external error redaction; loopback APIの無効化・非loopback拒否・health/details・404/405・no-store・単一details snapshot置換・停止後のport解放・公開DTOのwhitelist。Windows clientのhealth readinessと固定details endpoint・transient SSH argv/非永続化・proxy/redirect拒否・1秒timeout・10秒poll/単一flight・details body上限・配列上限・unknown/missing/wrong-type/duplicate JSON key・数値/Unicode境界・generation fingerprint・state/null/stale表示。
- Static gates: `cargo clippy --all-targets --all-features --locked -- -D warnings`, explicit-unsafe search, secret-pattern scan, and shell invocation review.
- Dependency gates: `cargo deny check advisories licenses sources` with the repository `deny.toml`. Record the cargo-deny version, command, UTC start/end, RustSec advisory database commit/hash, registry/source set, exit code, and redacted result in the acceptance evidence. Known vulnerability, unsoundness, rejected-license, or rejected-source findings must be 0. A maintenance-only advisory may be excepted only by exact RustSec ID with a reason naming the transitive owner and absence of a safe upgrade; the three current Slint transitive exceptions are listed in `deny.toml`, and any new maintenance advisory fails closed. Tool absence, advisory database fetch/update failure, malformed output, or incomplete target graph is `INCONCLUSIVE` and delivery fails.
- Independent security evaluator: inspect the final source and raw command evidence without receiving the implementer's conclusion. Any unresolved finding at any severity fails R17; an environmental trust assumption must be stated as an assumption rather than waived as a product finding.

## Failure behavior

Malformed structured input, numeric domain/overflow violation, unsafe path/executable/URL, authentication URL length overflow, and invalid API listener configuration are rejected. Control-bearing and over-limit non-secret display text is deterministically normalized/shortened as control 7 specifies. On the first failure no synthetic quota/thread value is shown; after a valid snapshot, the entire last snapshot is preserved atomically. An invalid API publication retains the prior public snapshot; an explicit invalid or non-loopback listener prevents startup rather than starting a different listener. The Windows client similarly keeps only its last validated v1 snapshot after a transport or response failure, marks it stale, and shows blank `未取得` values on a first failure. Either outcome shows only a bounded generic status, avoids opening a rejected URL or file, terminates/reaps an unusable child, and keeps Main/Graph responsive. Security failure must not trigger window recreation, size repair, destructive DB recreation, or unchanged retry loops.
