# 導入と起動ガイド

## 目的

Codex Infoを公開ReleaseのLinux bundleから導入し、認証状態・レートリミット・利用履歴をX Windowで確認できる状態にします。

## 全体の流れ

1. 事前準備を確認する  
2. exact 5 assetのstable `windows-vX.Y.Z` ReleaseからLinux bundleをdownloadする
3. checksumを検証し、bundleをextractしてinstallする
4. service statusとloopback healthを確認する
5. boot/daily自動更新と手動確認方法を確認する
6. Codex認証を完了し、起動後の画面を確認する

この順で進めると、失敗が起きた場合の原因を切り分けしやすくなります。

## 事前準備

### 1) X Windowの起動確認

WSLg/ X サーバーが利用可能であることを確認します。

```bash
echo "$DISPLAY"
```

空文字や未設定なら、まずその環境の表示設定を直してください。

### 2) codex CLI

Codex App Server接続を行うので、次が通るかを確認します。

```bash
codex login status
codex app-server --help
```

`codex login status` がコマンドとして動くこと、`codex app-server --help` がヘルプを表示することが最低条件です。

## Linux bundleのdownload・検証・導入

### 1. Release assetをdownload

公開済み・stableな`windows-vX.Y.Z` Releaseから、同じversionのLinux 3 assetをdownloadします。
Release全体はWindows 2 assetとLinux 3 assetのexact 5 assetだけを持つ必要があります。
`CodexInfo.WindowsClient.Setup.exe`、`CodexInfo.WindowsClient.update.json`、
`x86_64-unknown-linux-gnu` archive、対応する`.sha256`、対応する`*.manifest.json`です。
draft、prerelease、partial、extra、malformed Release、導入済みversion以下のReleaseは使いません。
`X.Y.Z`はReleaseのversionへ置き換えてください。

```bash
version='X.Y.Z'
asset="codex-info-${version}-x86_64-unknown-linux-gnu.tar.gz"
checksum="${asset}.sha256"
manifest="${asset%.tar.gz}.manifest.json"
bundle_dir="$HOME/.local/share/codex-info/bundle-v${version}"
mkdir -p "$bundle_dir"
# 上記ReleaseからLinuxの3 assetをbundle_dirへ置く。
```

targetは`x86_64-unknown-linux-gnu`に固定です。利用できる互換性情報はmanifestの実測
`glibc_minimum`だけであり、そのminimum未満の環境では導入しません。他のdistributionや
architectureへの対応、署名済み、publisher検証済みとは表明しません。
導入には`bash`、`tar`、`sha256sum`、`python3`、`curl`、`flock`、user-systemd（`systemctl --user`）が必要です。

### 2. checksumとmanifestを検証

```bash
(cd "$bundle_dir" && sha256sum -c "$checksum")
test -s "$bundle_dir/$manifest"
```

checksum、manifest、archive contentの検証に失敗した場合はextractやinstallへ進まず、assetをReleaseから再取得します。
検証できないReleaseは採用せず、既存の導入状態も変更しません。

### 3. bundleをextractしてinstall

```bash
mkdir -p "$bundle_dir/extracted"
tar -xzf "$bundle_dir/$asset" -C "$bundle_dir/extracted"
bash "$bundle_dir/extracted/install.sh" \
  --bundle "$bundle_dir/$asset" \
  --manifest "$bundle_dir/$manifest" \
  --sha256 "$bundle_dir/$checksum"
```

bundleには`codex_info`、`codex-info.service`、永続化する`install.sh`、`codex-info-update.service`、
`codex-info-update.timer`、license/notice、version/target情報が含まれます。導入時は`install.sh`を
`$HOME/.local/libexec/codex-info-install.sh`へ、installed manifestを`$HOME/.local/share/codex-info/manifest.json`へ置きます。
repository clone、Cargo、ソース取得はこの導入に必要ありません。

### 4. statusとhealthを確認

```bash
systemctl --user status codex-info.service --no-pager
curl --fail http://127.0.0.1:8787/v1/health
```

healthのversionがReleaseの`X.Y.Z`と一致しない場合は利用を開始せず、導入をやり直します。

## 自動更新と手動確認

導入後のuser-systemd timerはboot時と毎日1回、固定repository `salty919/codex_info_v2`の公開Releaseだけを確認します。
導入済みversionより新しいstable Releaseでexact 5 assetが同居する場合だけ、identity、checksum、manifest、archive contentを
検証した後に既存のatomic install、`codex-info.service`再起動、health確認を行います。新版がない、draft/prerelease、
partial、extra、malformed、identity不一致、検証・service切替・health失敗のいずれでも導入状態を変更せず、更新失敗時は
旧binary、旧unit、`$HOME/.local/libexec/codex-info-install.sh`、profile dataへrollbackします。途中fileは残しません。

今すぐ確認する場合は次を実行します。

```bash
systemctl --user start codex-info-update.service
systemctl --user status codex-info-update.service --no-pager
systemctl --user status codex-info-update.timer --no-pager
journalctl --user -u codex-info-update.service --no-pager
```

最後のコマンドで更新確認、候補拒否、適用、rollbackの結果を確認できます。

### 5. 履歴保存先を明示する（任意）

履歴を別先に置きたい場合は起動前に設定します。

```bash
CODEX_INFO_DATA_DIR="$PWD/data" "$HOME/.local/bin/codex_info" --ui
```

## bundle導入を外す

bundleを残したまま、次のコマンドでdaemonの自動起動、自動更新、unitを解除します。

```bash
bash "$bundle_dir/extracted/install.sh" --remove
```

この操作は`codex-info.service`と`codex-info-update.service`/`.timer`を停止・無効化してunitを削除しますが、
`$HOME/.local/bin/codex_info`、`$HOME/.local/libexec/codex-info-install.sh`、installed manifest、履歴DB、DB backup、`history/usage_reset_hint.json`、Codex session JSONL、
設定を削除しません。履歴データの削除は別の明示操作です。

## 初回認証フロー（確実版）

1. 画面の「認証を開始」を押す  
2. 表示された「認証ページを開く」を押す  
3. ブラウザでOpenAIへログインし、Codexアクセス許可を完了する  
4. X Windowへ戻り「認証状態を確認」を押す  
5. メイン画面の状態が認証済みに切り替わることを確認する

上記で変化がない場合は、  
`codex login status` でCLI側認証状態を確認し、必要なら手順2〜4を再実行してください。

## 初回起動後の確認ポイント（最短チェック）

1. メイン画面が起動し、認証済みと表示される  
2. 残量とリセット時刻が更新される  
3. 7セルゲージの向き・比率が変化する  
4. 法的通知が開ける  
5. Graphを開ける  

ここで最低1つでも詰まると、環境・認証・データ取得のいずれかを疑います。

## 画面・状態確認用環境変数

実際のレビューや再現確認で使う状態は次です。

- `CODEX_INFO_PREVIEW=auth`
- `CODEX_INFO_PREVIEW=normal`
- `CODEX_INFO_PREVIEW=warning`
- `CODEX_INFO_PREVIEW=reset-warning`
- `CODEX_INFO_PREVIEW=error`
- `CODEX_INFO_PREVIEW=zero`
- `CODEX_INFO_PREVIEW=full`
- `CODEX_INFO_PREVIEW=monthly`
- `CODEX_INFO_PREVIEW=unlimited`
- `CODEX_INFO_PREVIEW=idle`
- `CODEX_INFO_PREVIEW=legal`
- `CODEX_INFO_PREVIEW=graph`
- `CODEX_INFO_PREVIEW=graph-old`

最小幅検証をする場合は次を加えて実行します。

```bash
CODEX_INFO_PREVIEW_SIZE=700x480 CODEX_INFO_PREVIEW=normal "$HOME/.local/bin/codex_info" --ui
```

## トラブルシュート

### 起動しない/真っ黒なとき

`DISPLAY`、`codex app-server --help`、`codex login status` を確認します。  
それぞれが成功していれば、次に`.log`の最終行を確認すると原因が絞れます。

### 認証後も未認証扱いのとき

`codex login status` を再実行し、ブラウザ側の許可結果を見直します。  
許可後にアカウント状態が更新されない場合は、ブラウザを閉じずに再試行します。

### 画面崩れ・はみ出し

```bash
CODEX_INFO_PREVIEW_SIZE=700x480 CODEX_INFO_PREVIEW=normal "$HOME/.local/bin/codex_info" --ui
```

で再現する状態で崩れるかを確認し、再現条件をメモしてください。
