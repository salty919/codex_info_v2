# 導入と起動ガイド

通常の利用ではsource repositoryをcloneせず、[最新のstable Release](https://github.com/salty919/codex_info_v2/releases/latest)からLinux bundleまたはWindows Setupを取得します。

## Linux / WSL側の準備

必要なものは次のとおりです。

- `x86_64-unknown-linux-gnu`を実行でき、bundle manifest記載の`glibc_minimum`以上を持つLinux環境
- `bash`、`tar`、`sha256sum`、`python3`、`curl`、`flock`、user-systemd
- `codex` CLI（`codex app-server --stdio`を実行できること）
- Linuxの画面を使う場合だけ、WSLgまたはX serverと設定済みの`DISPLAY`

```bash
codex login status
codex app-server --help
```

## Linux bundleを導入する

stableな`windows-vX.Y.Z` Releaseは、Windows 2 assetとLinux 3 assetの5件で構成されます。Linuxへは同じReleaseから次の3件を取得します。

- `codex-info-X.Y.Z-x86_64-unknown-linux-gnu.tar.gz`
- `codex-info-X.Y.Z-x86_64-unknown-linux-gnu.tar.gz.sha256`
- `codex-info-X.Y.Z-x86_64-unknown-linux-gnu.manifest.json`

`X.Y.Z`はReleaseのversionへ置き換えます。

```bash
version='X.Y.Z'
asset="codex-info-${version}-x86_64-unknown-linux-gnu.tar.gz"
checksum="${asset}.sha256"
manifest="${asset%.tar.gz}.manifest.json"
bundle_dir="$HOME/.local/share/codex-info/bundle-v${version}"
mkdir -p "$bundle_dir"
# 同じReleaseのLinux 3 assetをbundle_dirへ置く
(cd "$bundle_dir" && sha256sum -c "$checksum")
test -s "$bundle_dir/$manifest"
mkdir -p "$bundle_dir/extracted"
tar -xzf "$bundle_dir/$asset" -C "$bundle_dir/extracted"
bash "$bundle_dir/extracted/install.sh" \
  --bundle "$bundle_dir/$asset" \
  --manifest "$bundle_dir/$manifest" \
  --sha256 "$bundle_dir/$checksum"
```

checksum、manifest、archive contentを検証できない場合はinstallへ進みません。draft、prerelease、不完全、
余分なassetを含むReleaseも使用しません。repository cloneとCargo buildは不要です。archive内の`run.sh`は
repository版とbyte-identicalなruntime launcherで、install後は`$HOME/.local/bin/codex-info`から使います。

導入後はserviceとversionを確認します。

```bash
"$HOME/.local/bin/codex-info" --status
```

`--status`がversion/source/manifest、systemd owner、process、lock、socket、healthの同一generationを
確認できない場合は利用を開始しません。healthの`product_version`一致だけでは成功としません。

## 起動モード

顧客向けに公開されるinstalled launcher操作は次のとおりです。RESTは`127.0.0.1:8787`固定です。

| 目的 | command | 動作 |
| --- | --- | --- |
| 常駐service | `$HOME/.local/bin/codex-info` または `--start` | stable reconcile後にmanaged daemonを有効化・起動 |
| Linux画面 | `$HOME/.local/bin/codex-info --ui` | 同じreconcile後に検証済みpayloadのX UIを表示 |
| 即時更新 | `$HOME/.local/bin/codex-info --update` | timerを待たず同じresolverを実行 |
| 整合確認 | `$HOME/.local/bin/codex-info --status` | 完全なgeneration/owner/health tupleをread-only表示 |
| 今回のbootだけ停止 | `$HOME/.local/bin/codex-info --stop` | main serviceだけ停止しtimerと次回bootは維持 |
| 自動起動も停止 | `$HOME/.local/bin/codex-info --disable-autostart` | main serviceとtimerを停止・無効化 |
| unit解除 | `$HOME/.local/bin/codex-info --remove` | main/update unitだけ解除しdata/programを保持 |
| ヘルプ | `$HOME/.local/bin/codex-info --help` | 状態を変更せず利用方法を表示 |

引数なしは画面を表示しません。Linux画面が必要な場合は`--ui`を明示します。`--port`、未知・混在引数は
mutation前に失敗します。raw payloadのport指定はservice/development用で、通常運用には使いません。

## 認証する

Linux画面を開いた場合は次の順で認証します。

1. 「認証を開始」を選ぶ
2. 「認証ページを開く」からブラウザへ移る
3. OpenAIアカウントでCodexへのアクセスを許可する
4. 画面へ戻り「認証状態を確認」を選ぶ

Codex Infoへpassword、API key、tokenを入力する必要はありません。認証とcredential保存はCodex CLIが担当します。

## 自動更新

installerは`codex-info-update.service`と`codex-info-update.timer`を配置します。timerは導入5分後と以後
1時間ごと（accuracy 1秒）に固定repositoryのhighest stable Releaseを確認します。launcher、service起動前、timer、
手動操作は同じresolverを使います。同versionでもlocal memberが不整合ならverified repairし、downgradeしません。
失敗時はverified旧世代をmanaged+healthyへ戻し、unknown/foreign ownerだけは無変更の`SAFE_BLOCKED`にします。

今すぐ確認する場合は次を使います。

```bash
"$HOME/.local/bin/codex-info" --update
"$HOME/.local/bin/codex-info" --status
systemctl --user status codex-info-update.timer --no-pager
journalctl --user -u codex-info-update.service --no-pager
```

## Windowsクライアントを導入する

1. Linux / WSL側で`codex-info.service`と`GET /v1/health`が正常であることを確認する
2. 同じstable Releaseの`CodexInfo.WindowsClient.Setup.exe`を取得する
3. 標準GUI Setupを実行し、ユーザー単位でインストールする
4. StartメニューからCodex Infoを起動する
5. 初期SetupでWSL、またはOpenSSH configに登録済みの`Host` aliasを選ぶ
6. SSH local port forwarding経由でLinux側の`127.0.0.1:8787`へ接続する

Linux側serviceを`0.0.0.0`やLAN addressへbindしません。Windows側にはpassword、token、private key、展開済み接続先を保存せず、再接続に必要な非秘密selectorだけを保存します。

Windows版は起動時に新しいReleaseの有無を確認し、通知だけを表示します。更新操作を選んだ場合だけSetupとmanifestを取得・検証し、標準GUI Setupを起動します。silent install、自動適用、自動再起動は行いません。

## 自動起動と更新を外す

```bash
"$HOME/.local/bin/codex-info" --disable-autostart
"$HOME/.local/bin/codex-info" --remove
```

`--disable-autostart`はunitを残し、`--remove`はmain/update unitだけを解除します。installed generation、
launcher、永続installer、manifest、履歴DB、backup、reset hint、gap/recorder/control state、Codex session JSONL、
設定は削除されません。履歴データの削除は別の明示操作です。

Windows版はWindowsの「インストールされているアプリ」から標準uninstallerを使います。Linux側のserviceと履歴はWindowsアプリのuninstall対象ではありません。

## 問題があるとき

Linux / WSL側から順に確認します。

```bash
"$HOME/.local/bin/codex-info" --status
journalctl --user -u codex-info.service --no-pager
journalctl --user -u codex-info-update.service --no-pager
codex login status
```

Linux画面だけが出ない場合は`echo "$DISPLAY"`も確認します。Windowsだけが接続できない場合は、Linux側healthを確認してから、選択したWSL profileまたはOpenSSH `Host` aliasを見直します。取得失敗時に最後の完全表示が残っていることは正常な失敗表示であり、空や0への初期化ではありません。
