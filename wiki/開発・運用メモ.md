# 開発・運用メモ

このページは開発者向けの入口です。製品仕様や顧客向けcommandの正本をWikiへ重複させず、repository内の文書へ接続します。

## 現在の構成

- Linux core: Rust / Cargo
- Linux GUI: Slint / X Window
- Windows client: Avalonia / .NET 10
- 履歴: SQLite
- account・quota取得: Codex App Server / JSON-RPC
- UI向け公開境界: loopback限定のread-only REST API v1
- 配布: 同一stable ReleaseにWindows Setup/update manifestとLinux archive/checksum/manifestを同居

データの流れは次の一方向です。

```text
Codex App Server + session JSONL
        ↓
Linux / WSL resident service（唯一のcollector・writer）
        ├─ SQLite history
        └─ immutable /v1/details snapshot
              ├─ Linux X UI
              └─ SSH local forwarding → Windows client
```

Main、Graph、Threadsの各adapterで再収集、再計算、複数endpointのmergeを行いません。候補が不完全な場合はsnapshot全体を採用せず、last-goodを保持します。

## 顧客導線と開発導線

顧客向け通常導線はRelease bundle / Setupです。repository cloneとCargo buildを顧客向けinstall手順へ混ぜません。
`run.sh`はrepositoryとbundleでbyte-identicalなruntime launcherであり、build機能を持たずinstalled
`$HOME/.local/bin/codex-info`へ委譲します。

顧客向けlauncherは引数なし/`--start`、`--ui`、`--update`、`--status`、`--stop`、
`--disable-autostart`、`--remove`、`--help`だけです。raw payload CLIの`--port PORT`は
service/development/E2E用で、launcherの更新・daemon管理authorityへ混ぜません。新しいmodeやfallbackをWikiだけで追加しません。

## UIを変更するとき

Linux UIの余白、色、文字、角丸は`ui/theme.slint`、共通部品は`ui/components.slint`を優先します。Windowsを含む表示意味、状態、順序は製品要件と画面仕様から導出し、platform adapterへ別の計算正本を作りません。

UI変更は対象platformの実画面で確認します。画像取得だけを合格根拠にせず、表示値、文言、状態、配置、操作を正本と照合します。実Windowsで未確認の項目はLinuxやmockの結果からPASSへ変換しません。
