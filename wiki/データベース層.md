# データベース層

## 定義

主なmaster IDは`RECORDER-MODEL-01`、`CUM-138-01..03`、`AUTH-129`、`GEN-129`、`DB-129`、`SESSION-129`、`LEGACY-129`です。製品全体の記録継続は`CUM-138-07`、API公開との境界は`REST-129`を参照します。

永続化はprofile・認証account・storage epochでpartitionし、UIやclient versionをDB identityに使いません。accountを推測できない結果は別accountのDBへ書かず、既存DBを削除・再生成して回復させません。

## 現行schema

実装入口は`src/account_scope.rs`と`src/usage_store.rs`です。`PRAGMA user_version`の現行値は`2`、partition metadataのschema tokenは`codex-info-account-db-v1`、profile registryは`codex-info-profile-scope-v1`です。これらは別のversion軸です。

| table | 責務 |
| --- | --- |
| `usage_history` | period/minute単位のquotaとlegacy累積履歴 |
| `durable_state` | recorderのdurable state |
| `recorded_sessions` | 収集済みSessionのlegacy inventory |
| `storage_partition` | profile/account/storage epoch identity |
| `collection_generation` | collector generationの状態 |
| `session_checkpoints` | source別cursor、prefix、前回累積 |
| `session_ranges` | 検証済み収集rangeとdigest |
| `session_model_totals` | Session単位の任意model累積 |
| `usage_model_history` | minuteごとの任意model履歴 |
| `history_continuity` | legacy回復の適用状態 |
| `recorder_gap_ledger` | confirmed gapと復旧状態 |

`usage_history`の固定3モデル列はlegacy互換値です。任意modelの正本はmodel行を持つtableであり、ASTRAや将来modelを「その他」へ消したり0と推測したりしません。

## transaction、migration、backup

- writerは単一profile owner、lease、generationを検証し、一つのSQLite transactionでcursor・range・model totals・historyをcommitします。
- migrationはtransaction内でschemaを検証し、未知のfuture `user_version`や余分なtable/columnを黙って変更しません。
- backupはSQLite online backupを使い、source DB/WAL/SHMとSession JSONLをread-onlyに保ちます。
- DB lock、disk full、I/O、migration、identity不一致では既存DBとlast-goodを保持し、同じbatchを二重加算しません。
- remote API障害中もlocal Session収集とDB記録は独立して継続し、quota未取得は`NULL`で保存します。
- retentionは現在から3暦月の閉区間です。削除対象外のDB、backup、Session、別owner dataを削除しません。
