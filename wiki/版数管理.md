# 版数管理

同じ「version」という語でもauthorityと変更条件は別です。相互に代用しません。

| version軸 | authority / 現行値 | 変更条件・意味 |
| --- | --- | --- |
| product | `Cargo.toml`、root `Cargo.lock`のproduct package、`windows-client/Directory.Build.props` | binary-impactのmain PRでbaseより大きいstable versionへ3箇所を同期。通常はpatchを増やし、minor/majorはユーザー専用main PRの明示差分で選ぶ。WFは変更しない |
| REST details | `src/server.rs`とWIRE owner / current `v3`、deprecated `v2`,`v1` | schema互換境界。product versionとは独立。healthはstable |
| SQLite `user_version` | `src/usage_store.rs` / `2` | transactionで行う物理schema migration。future versionはfail-closed |
| storage metadata | `codex-info-account-db-v1` | partition identity形式。`user_version`とは別 |
| profile registry | `codex-info-profile-scope-v1` | profile scope metadata形式。product/API versionとは別 |
| storage epoch | DB/profile stateの単調epoch | account partition世代。Release番号ではない |
| bundle manifest | build scriptのmanifest schema・product version・source SHA・member digest | 一つのLinux candidate identityを固定 |
| Windows update manifest | Windows update schema・product version・installer digest | 同じstable Release内のWindows candidate identity |
| Release | `windows-vX.Y.Z` | 同versionのWindows 2 asset＋Linux 3 assetを一つのpublished Releaseとして扱う |
| main quality revision | main向けPRのimmutable head SHAと同じheadの最新quality run（attempt 1のみ） | Workflowはbranchやversionを変更せず、PRに記録済みのproduct versionを検証する。binary impact時だけ同じheadの候補artifactを要求し、non-binary時は公開しない |

画面はproduct versionを表示します。client/daemonのproduct version差だけでAPIを拒否せず、schema互換性で判定します。API version追加でDB migrationを必須にせず、UI変更でAPI/DB versionを上げません。

master IDは`VER-FORWARD-01`、`WF-SERIAL-01`、`API-LIFECYCLE-01`、`API-DEPRECATION-01`、`DB-129`です。実装入口は`Cargo.toml`、root `Cargo.lock`、`windows-client/Directory.Build.props`、`src/server.rs`、`src/usage_store.rs`、各bundle/update manifest生成処理です。直接oracleは`scripts/product_version.py`とその既存fixture、WIRE/server client contract、usage store migration case、bundle/Windows manifest testです。
