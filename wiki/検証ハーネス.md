# 検証ハーネス

## 開発プロダクトライン

```text
仕様 → 影響評価 → 正本/台帳更新 → 実装 → 直接確認 → 統合確認 → 最適化
```

この有限ループはcalendar cronではなく、要求の追加・変更、障害の記録、Release準備の各節目で必ず1回起動します。同じrevisionを定期pollしたり、変更していない全領域を再評価したりしません。

| phase | 入力 | 出力 / 次へ進む条件 | 停止条件 |
| --- | --- | --- | --- |
| 仕様 | raw要求、障害事実 | owner、master ID、受入条件、非対象が一意 | 振る舞いを変える曖昧さ、authority不明 |
| 影響評価 | 変更予定のmaster IDとpath | DB/API/UI/Release/運用への波及と依存順を有限化 | 既存ownerとの競合、保護対象が不明 |
| 正本/台帳更新 | 合意済みscope | owner文書と派生台帳が同じIDを指す | 正本同士の矛盾、旧仕様が優先される状態 |
| 実装 | 固定した正本とscope | owner境界内の最小変更 | 未宣言pathや保護対象への波及 |
| 直接確認 | 変更した観測結果 | その結果を直接判定する最小oracleのPASS | 0件、SKIP、別revision、推測だけの結果 |
| 統合確認 | 完全diffと直接証拠 | 影響ownerの結果、必要時だけ実OS/installer/実画面 | candidate不一致、必要証拠の欠落 |
| 最適化 | 今回の仕様・diff・評価結果 | superseded仕様、重複owner/test、未変更領域check、反復失敗gateを除去し、残件をIssueまたはINCONCLUSIVEへ記録 | 削除対象の独立価値・ownerが不明 |

最適化は「確認を増やす工程」ではありません。新要求が入るたびに全体の依存方向を見直し、旧要求をhistorical/deprecatedへ限定し、同じ観測結果を二重に判定するtestや、変更と因果関係のないcheckを残さない工程です。品質を守る最小集合が確定したらそのloopは終了します。calendar job、新CI job、全suite、全model直積、routine AI reviewは追加しません。

## 一方向の流れ

```text
全changed paths
  → ci_change_scope.py（owner / binary impact / language）
  → quality_plan.py（有限profile / check集合）
  → pre_pr_gate.sh（localで各checkを1回）
  → feat PRの選択owner job（advisory）
  → main Release candidateの選択owner job + acceptance
  → 変更境界に必要な場合だけ実OS・installer・実画面
```

## componentと責務

| component | 判定すること | 判定しないこと |
| --- | --- | --- |
| `requirements_authority.py` / `requirements_ledger_gate.sh` | owner registry、master ID、派生台帳の参照一意性 | 製品動作、remote状態 |
| `ci_change_scope.py` | rename/copy両端を含むpath→owner/language/binary impact | testの成否 |
| `quality_plan.py` | 登録済みprofileと要求checkの有限選択 | 未変更ownerの念押しcheck |
| `pre_pr_gate.sh` | 選択済みlocal checkを各1回呼ぶ | PR/Actionsの代替実験、同じ失敗のrerun |
| `regression_guard.sh` | 選択されたRust format/test/profile case | Windowsやdistribution |
| `windows_client_contract_gate.sh` | 選択されたWindows restore/format/unit | 未変更Linux製品 |
| `workflow_quality_gate.py` | Workflow構造の有限fixture | 実製品の正常表示 |
| `selected_quality_gate.py` | main Release結果のselected/non-selected集約 | feat PRのmerge禁止 |
| X11 / Windows E2E | 変更された実画面・OS・installer境界 | 全変更への一律追加 |

## 仕組みの一覧

| 種類 | 仕組み | 役割 | 境界 |
| --- | --- | --- | --- |
| 仕様 | owner registry / requirements ledger / GitHub Issue | 一意なowner、master ID、作業scope、未解決事項を追跡 | WikiやIssueだけで実装済み・PASSを決めない |
| local harness | `requirements_authority.py`、`ci_change_scope.py`、`quality_plan.py`、`pre_pr_gate.sh` | 正本整合、完全diff分類、有限check選択、PR前の一度の実行 | remote/実OSの結果を推測しない |
| remote harness | `feat-integration.yml`、`version-prepare.yml`、`selective-quality.yml`、`release.yml` | feat advisory、main Release品質、candidate/publicationを別経路で扱う | PRを実験場所にせず、Workflow結果をユーザー判断の代替にしない |
| 境界harness | Rust/Windows contract gate、X11/Windows E2E、distribution check | 変更したownerの直接caseと、必要時だけ実環境境界を確認 | docs-only変更や未変更ownerへ一律適用しない |
| agent skill | `close-requirements-with-evidence` | 複合要求、過去デグレード、厳密な要求閉包を条項と証拠で管理 | 製品authority、test oracle、PASS証拠ではない |
| agent skill | `cost-aware-agent-delegation` | 委譲が実際に速度・品質へ寄与する場合だけ役割と消費を最小化 | 固定model指定やroutine reviewを要求しない |
| agent skill | `codex-info-live-release-check` | exact Windows Release candidateとlive Linux/WSLの最終境界を確認 | 通常unit、fixture、docs変更には使わない |

skillはその実行環境の利用可能catalogで存在を確認してから使います。利用不能なら名前や結果を捏造せず、同じ受入条件を判定できるdeterministicな既存harnessへ戻すか、未確認として報告します。skillの説明は作業手順であり、製品仕様の正本、直接oracle、ReleaseのPASS証拠にはなりません。

## 最小で十分な確認

- master IDごとに観測結果を直接判定するoracleを少なくとも1件持ちます。
- 同じ観測結果のcheck ownerは1件です。別gateからtest名や文字列を二重監視しません。
- 変更していない製品owner、実OS、installer、全model直積、全suiteを「念のため」実行しません。
- 0件、SKIP、INCONCLUSIVE、過去revisionのPASSを現行PASSへ変換しません。
- 実環境だけで得られる証拠はlocal PASSへ混ぜず、未確認のまま残します。
- 新checkは、既存checkで観測できない独立境界とmaster IDがある場合だけ追加します。

docs-only変更はDOCS ownerとauthority整合だけを選び、Linux/Windows buildや実画面を実行しません。PR前にremoteでしか得られない証拠を要求する循環も作りません。

## 定義・検証状態

- owner / master ID: `PRODUCT`の`WF-BINARY-IMPACT-01`、`WF-FEAT-SELECTIVE-01`、`WF-QUALITY-ONCE-01`、`WF-NONBLOCKING-QUALITY-01`と、各製品ownerの直接master ID。
- 実装入口: `scripts/requirements_authority.py`、`scripts/ci_change_scope.py`、`scripts/quality_plan.py`、`scripts/pre_pr_gate.sh`、`.github/workflows/*.yml`。
- 直接oracle: authority gate、selector/quality planの既存finite fixture、選択ownerの直接case、境界変更時だけの実OS evidence。
- 未確認の扱い: current revisionへ直接結び付かない結果、公開Wiki未同期、remote/実OS未実施は`INCONCLUSIVE`です。このページ自体を実装済み・Release PASSの証拠にしません。
